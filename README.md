# מתכונים — Yossipof-Recepies

אפליקציית ניהול מתכונים משפחתית. כל המשתמשים רואים את כל המתכונים, כל אחד
עורך את שלו, וכל מתכון מגיע עם פירוק אוטומטי לשדות וערכים תזונתיים.

אפליקציית PWA — אפשר להתקין אותה למסך הבית בטלפון והיא עובדת גם ללא רשת
(קריאה בלבד).

## מה יש באפליקציה

- **מסך ראשי** עם כל המתכונים בריבועים: תמונה, שם, ומי העלה (שם ותמונה קטנה).
  בכותרת — חיפוש מתכון וכפתור הוספה (+) גדול לצידו.
- **סינון בשורה אחת**: כפתור «מועדפים» וכפתור «קטגוריות» שפותח חלון עם חיפוש,
  מספר מתכונים לכל קטגוריה, ובחירה מרובה. השורה נשארת באותו גובה גם כשיש
  עשרות קטגוריות, ומתכון מוצג אם הוא שייך לאחת מהנבחרות.
- **הוספת מתכון** מתוך אחד מחמישה מקורות: הדבקת טקסט, העלאת קובץ
  (Word / טקסט / PDF / תמונה), בחירת קובץ מ-Google Drive, תמונה מהגלריה, או
  קישור לדף מתכון. ה-AI מפרק את המקור לשדות — **שם המתכון**, **רכיבים**,
  **אופן ההכנה**, **הערות** ו**תמונה** — ומעצב את הרכיבים שורה לשורה.
  מסמכי Word (docx.) נקראים בדפדפן עצמו, וההדגשות שבהם נשמרות.
- **שמירה על העיצוב**: אם הטקסט שהודבק מכיל הדגשות, הן נשמרות גם אחרי הפירוק
  לשדות וגם בעריכה. השדות נשמרים כ-HTML מסונן.
- **ערכים תזונתיים**: קלוריות, חלבון ושומן לכמות הכוללת, וטבלה שמראה כמה יוצא
  לכל חלק לפי הצעות החלוקה של ה-AI — או לפי כל חלוקה אחרת שתזינו.
- **המתכון נשמר רק בלחיצה על "שמירה"**, והכול ניתן לעריכה תמיד.
- מועדפים, קטגוריות מרובות לכל מתכון, מסך ניהול קטגוריות וסינון לפיהן.
- הזדהות מלאה: כניסה, הרשמה, החלפת סיסמה, שכחתי סיסמה ואיפוס, והגדרות משתמש
  עם שם ותמונה.

## הרצה מקומית

```bash
npm install
cp .env.example .env   # ומלאו את הערכים מ-Supabase
npm run dev
```

| `VITE_SUPABASE_URL` | Supabase Dashboard → Project Settings → Data API |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Supabase Dashboard → Project Settings → API Keys |

את אותם משתנים צריך להגדיר גם אצל ספק האחסון (Netlify / Vercel).

## בחירת קובץ מ-Google Drive

כל משתמש מייבא מה-Drive **שלו**: הבחירה נעשית ב-Picker הרשמי של גוגל, שנפתח על
החשבון שאיתו המשתמש מזדהה, והאפליקציה מקבלת רק את הקובץ שנבחר — לא גישה לשאר
ה-Drive. זה בדיוק מה שה-scope `drive.file` נותן, והוא גם ה-scope שאינו דורש
אימות אבטחה של גוגל, ולכן כל בני המשפחה יכולים להשתמש בזה ולא רק חשבונות
ברשימת Test users.

הקובץ יורד בדפדפן עם ה-token של הבחירה: הוא לא חייב להיות משותף לכל מי שיש לו
קישור, וה-token לא נשלח לשרת — רק הטקסט (או בייטים של PDF / תמונה) מגיעים
לפונקציית הפירוק. מסמכי Google מיוצאים לטקסט, גיליונות ל-CSV.

בפרויקט ב-Google Cloud Console צריך:

1. להפעיל את **Google Picker API** ואת **Google Drive API**.
2. במסך ההסכמה (OAuth consent screen) לבחור **External**, ולפרסם את האפליקציה
   (Publish app) כדי שכל אחד יוכל להתחבר ולא רק Test users.
3. ליצור **OAuth client ID** מסוג Web, ולרשום ב-Authorized JavaScript origins
   את כתובות האפליקציה (`http://localhost:5178` ואת כתובת הפרודקשן).
4. ליצור **API key** ולהגבילו ל-Google Picker API ולאותם origins.

אם אחד משלושת המשתנים חסר, אפשרות ה-Drive חוזרת לשדה של קישור שיתוף ציבורי.

## הקמת Supabase

האפליקציה חולקת את פרויקט ה-Supabase עם אפליקציית רשימת הקניות
(`Yossipof-Shopping`), כי התוכנית החינמית מוגבלת לשני פרויקטים פעילים. כדי שלא
תהיה התנגשות, כל הטבלאות של המתכונים נושאות קידומת `recipe_`, וכל הרשאות ה-RLS
שלהן דורשות משתמש מחובר — בעוד שרשימת הקניות מזוהה לפי מספר טלפון ואינה נוגעת
ב-Auth או ב-Storage כלל. בונוס לא מתוכנן: השימוש היומיומי ברשימת הקניות מונע
מהפרויקט להיכנס להשהיה אחרי שבוע חוסר פעילות, ולכן גם המתכונים תמיד זמינים.

1. הריצו את `supabase/setup.sql` ב-SQL Editor של הפרויקט. הוא יוצר את הטבלאות,
   את הרשאות ה-RLS ואת שני הבאקטים לתמונות, וניתן להרצה חוזרת בבטחה.
2. הגדירו את הסוד `GEMINI_API_KEY` ב-Edge Functions → Secrets.
3. פרסמו את הפונקציה `parse-recipe` שב-`supabase/functions/parse-recipe`.

אפשר לבחור מודל אחר דרך הסוד `GEMINI_MODEL`.

### הגדרות Authentication

- **Confirm email** מכובה: ההרשמה מיידית, ללא מייל אימות. השירות החינמי של
  Supabase מוגבל לכשני מיילים בשעה, ואיפוס סיסמה חשוב יותר מאימות כתובת.
- **Site URL** ו-**Redirect URLs** חייבים להצביע על הכתובת שממנה האפליקציה
  מוגשת, אחרת הקישור במייל של "שכחתי סיסמה" יוביל לשום מקום. בפיתוח מוגדר
  `http://localhost:5178`; אחרי פריסה יש לעדכן לכתובת האמיתית ולהשאיר את
  localhost ברשימת ההיתר.

## מבנה הנתונים

| טבלה | תפקיד |
| --- | --- |
| `recipes` | המתכון עצמו. שדות הטקסט נשמרים כ-HTML. |
| `recipe_profiles` | שם ותמונה לכל משתמש. נוצר אוטומטית בהרשמה. |
| `recipe_categories` | רשימת הקטגוריות, משותפת לכל המשתמשים. |
| `recipe_category_links` | שיוך מתכון לקטגוריות (רבים לרבים). |
| `recipe_favorites` | מועדפים, פרטיים לכל משתמש. |

הרשאות: כל משתמש מחובר קורא הכול; כתיבה, עריכה ומחיקה של מתכון — רק לבעליו.
